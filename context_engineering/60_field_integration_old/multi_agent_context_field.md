# 多 Agent 上下文场

## 从离散上下文到上下文场

传统做法: 每个 Agent 独立接收上下文, 互不关联 (孤立模式)。

上下文场 (Context Field): Agent 间的上下文形成**连续的语义场**,
信息在场中流动, 上游输出自然成为下游输入, 形成递归叠加。

这不是抽象比喻。CIM 项目的 9-Agent 系统中, 上下文确实像物理场一样传播:
- 有源头 (Agent-01/02/03 的初始建模)
- 有梯度 (从粗粒度拓扑到细粒度控制)
- 有边界 (Named Graph 隔离)
- 有叠加 (Agent-09 汇聚所有场)

| 特性 | 系统拓扑场 | 设备实例场 | 控制场 | 集成验证场 |

## MVP 安全事件的上下文场

L2 电气火灾响应场景展示了上下文场如何在应用层递归叠加:

```
Layer 1: BAS 传感场 (1,055 BACnet 点位)
    │
    │  SimClock 时间注入 (t0→t1→t2)
    ▼
Layer 2: FAS 探测场 (62 探测器, 26 类 SecurityEvent)
    │
    │  EventEngine SPARQL 扫描
    │  SELECT ?event WHERE { GRAPH <graph/event> { ... } }
    ▼
Layer 3: 事件处置场 (10 action nodes, 5-state machine)
    │
    │  ActionChain 顺序执行
    │  IDLE → DETECTED → CONFIRMED → RESPONDING → RESOLVED
    ▼
Layer 4: 态势感知场 (可视化平台)
    │
    │  WebSocket 实时推送
    ▼
Layer 5: 决策场 (运维人员界面)
```

每一层的上下文场都是下一层的输入:
- BAS 传感数据是 FAS 探测的上下文
- FAS 探测结果是事件处置的上下文
- 事件处置状态是态势感知的上下文
- 态势全景是人工决策的上下文

## 上下文场的数学描述

定义上下文场函数:

```
F(x, t) = 在位置 x (Agent) 和时间 t 的上下文向量

其中:
  x ∈ {Agent-01, Agent-02, ..., Agent-09}
  t ∈ {t0 (正常), t1 (异常), t2 (告警)}
```

场梯度:
```
∇F = F(Agent-09, t) - F(Agent-01, t)

Agent-01 的上下文: ~60 类, 系统级
Agent-09 的上下文: 545 类, 全局级

梯度方向: 从局部到全局, 从粗粒度到细粒度
```

场叠加:
```
F(Agent-09, t) = Σᵢ F(Agent-i, t)  for i = 01..08

Agent-09 的上下文是所有 Agent 输出的叠加。
但不是简单的拼接 — 是通过 SPARQL 联合查询的语义融合。
```

## 场边界: Named Graph 作为隔离机制

Named Graph 定义了上下文场的边界:

```
graph/tbox ──── 本体定义场 (只读, 所有 Agent 共享)
graph/ifc  ──── BIM 静态场 (只读, 建筑不变)
graph/bas/* ─── BAS 动态场 (读写, 3 快照轮换)
graph/cmms ──── 维保历史场 (月度更新)
graph/fas  ──── 安防拓扑场 (MVP 核心)
graph/event ─── 安全事件场 (实时, 无缓存)
```

场边界确保:
- Agent-06 不会意外修改 Agent-02 的空间数据
- MVP EventEngine 只扫描 graph/event 和 graph/fas, 不受 CMMS 噪声干扰
- 验证时 Agent-09 可以跨越所有边界, 但生成时每个 Agent 只在自己的场内操作

## 实践启示

1. **设计上下文场, 而非设计提示词**
   不要问 "给 Agent-03 什么 prompt", 要问 "Agent-03 处于什么上下文场中"。

2. **场的连通性决定系统质量**
   如果 Agent-01 的输出无法传播到 Agent-05, 耦合关系就会断裂。
   上下文契约保证了场的连通性。

3. **场的隔离性防止污染**
   Named Graph 是硬隔离。没有隔离, Agent-08 的维保数据会成为 Agent-06 的噪声。

4. **MVP 是场叠加的验证**
   L2 火灾场景从 BAS→FAS→Event→Action→Display, 验证了 5 层场的叠加是否正确。
   如果 step12 通过, 说明上下文场的端到端传播是完整的。
